Истёкшее, уже полученное и повторное событие не тревожит пользователя. После тихих часов можно оповестить только об актуальной акции. Отказ в разрешении не скрывает раздачи. |
| Этапы 1–3, Compose и ручная проверка | Первая установка, пустая лента, частичный сбой, офлайн с кэшем, переход из уведомления при закрытом приложении и возврат из браузера. Отдельно проверить устаревшую карточку и завершённую раздачу. | Текст различает состояния «Раздач нет» и «Не удалось проверить». Нажатие ведёт к конкретному предложению или к его завершённой записи. В истории сохраняется отметка пользователя. |

После добавления Gradle-проекта локальный прогон на Windows начинается с `.\gradlew.bat :app:lintDebug :app:testDebugUnitTest :app:assembleDebug`. Для подключённого эмулятора или телефона — `.\gradlew.bat :app:connectedDebugAndroidTest`. Результат прогона привязать к ревизии проекта и API устройства. На этапе кандидата дополнительно запускать lint и сборку варианта release, проверять объединённый манифест, установку и основные сценарии именно в подписанном APK.

Живые запросы запускать отдельно от повторяемых тестов. Сравнить Android и расширение для тех же магазинов, стран и близкого времени. Записать дату, страну, статус источника, ID и различия без личных данных. Пропущенную реальную акцию разобрать по сохранённому ответу, при изменении правил добавить минимальный тестовый пример. ## Матрица устройств и полевой прогон

| Среда | Зачем и как проверить |
|---|---|
| API 26, эмулятор AOSP | Нижняя граница. Установка, миграция, каналы, лента и переход в магазин через системный браузер. Базовый цикл должен работать без сервисов Google. |
| API 33, чистая установка | Разрешить, отклонить и позднее включить уведомления через настройки системы. Проверить каждый канал отдельно. |
| API 35–37, эмуляторы | Edge-to-edge, системные отступы, жест «Назад», поворот, изменение размера окна, телефон и широкое окно от 600 dp. На API 37 проверить актуальные ограничения адаптивности. |
| Физический телефон со стандартным Android и устройство с ограничениями фоновой работы производителя, если доступно | Проверить на штатных настройках несколько часов с выключенным экраном, ночью, в Doze и энергосбережении. Отключить сеть, вернуть её, перезагрузить телефон. Отдельно проверить принудительную остановку и восстановление после ручного открытия приложения. Записать модель, ОС, режим батареи и доступные результаты. |
| Узкое и широкое окно, RU/EN | Пройти основной путь в обеих темах, с крупным шрифтом до 200% и с TalkBack. Название, полный срок и обе кнопки должны читаться и нажиматься. Проверить порядок фокуса, текстовые метки и доступность отметки без жеста смахивания. Сохранить снимки ленты, пустого состояния и ошибки. |

**Полевой замер.** Предлагаемый старт — 48 часов с интервалом 3 часа на каждом доступном физическом телефоне. В локальном журнале записать плановое окно, фактическое начало и завершение опроса, результат по магазину, время системной публикации и число/объём запросов. Время появления видимого уведомления записывает тестировщик. Отдельно показать медиану и худшую задержку, число пропущенных окон и акций, завершившихся до оповещения. Сравнить трафик и статистику батареи с таким же периодом при отключённом опросе. Два дня наблюдения дают начальную оценку только для проверенных устройств.

**Решение о бете.** На контрольных сценариях допускается ноль ложных раздач, повторных оповещений об одной кампании, переходов на неверную страницу и потерь отметок при обновлении. На физических устройствах подтвердить хотя бы один самостоятельный фоновый цикл с видимым уведомлением и переходом при выключенном до доставки экране. Тестовые события помечать в протоколе. Полезность беты затем проверить на нескольких реальных раздачах по добровольным отзывам — успел ли игрок забрать игру благодаря телефону и повторилось ли это. При систематических пропусках на штатных настройках зафиксировать устройство и исправить причину либо пересмотреть обещания продукта до публичного выпуска.

## Один APK для GitHub Releases и Obtainium

1. До первой распространяемой сборки выбрать постоянный `applicationId` (предложение — `bz.fgw.android`) и отдельный суффикс `.debug` для разработки. У APK своя версия, независимо от расширения. При каждом выпуске увеличивать `versionCode`, тег `vX.Y.Z` согласовать с `versionName`. Для бета-тегов явно обозначить prerelease.
2. Собрать универсальный release APK из фиксированного коммита. Долгоживущий ключ выпуска хранить отдельно от репозитория, с зашифрованной резервной копией и проверенным восстановлением. Для ранней локальной репетиции использовать отдельный тестовый ключ. Выполнить `apksigner verify --verbose --print-certs`. Проверить ID и версию из готового APK, зафиксировать SHA-256 файла и отдельно SHA-256 сертификата. Сборка release без доступа к секретам должна выдавать неподписанный APK, пригодный для независимой пересборки.
3. Локально собрать версии N и N+1 с одинаковым ID и тестовым сертификатом. Установить N, сохранить отметку, настройки и историю, обновить через `adb install -r`, сверить данные и единственность расписания. Проверить миграцию схемы Room и отказ установки версии с другим ключом в отдельном тестовом профиле. Обновление через ADB проверяет совместимость пакетов.
4. После решения о публикации прикрепить к GitHub Release один файл `Free-Games-Watcher-Android-X.Y.Z.apk`, контрольную сумму и заметки на русском и английском. В заметках указать минимальный Android, изменения и отпечаток сертификата. После публикации скачать APK, сверить хеш и подпись. Проверить прямую установку через браузер на обычном устройстве, включая системное разрешение выбранному источнику.
5. Источник в Obtainium — `https://github.com/Grim1313/Free-Games-Watcher-Android`. Для страницы загрузки подойдёт `obtainium://add/https://github.com/Grim1313/Free-Games-Watcher-Android`. Рядом оставить прямую ссылку на APK. После двух доступных выпусков проверить обнаружение N+1, выбор нужного APK и обновление поверх N, в том числе после первоначальной установки через браузер. Учитывать запросы подтверждения Android и настройку prerelease в Obtainium. Поддержку реального канала считать подтверждённой после этого прогона. [Ссылки Obtainium](https://wiki.obtainium.imranr.dev/deep_links/) · [Подпись Android](https://developer.android.com/studio/publish/app-signing)

На дату плана официальный FAQ относит первый этап Android developer verification к участвующим магазинам в отдельных регионах. Прямая установка APK пока вне этого этапа. Перед публичным выпуском заново проверить правила для стран беты, источника установки и сертифицированных устройств, особенно если выпуск сдвинется на 2027 год. [FAQ Android](https://developer.android.com/developer-verification/guides/faq) · [Календарь для распространителей](https://developer.android.com/developer-verification/guides/distributor-resources)
