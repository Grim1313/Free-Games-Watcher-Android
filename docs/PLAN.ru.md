# План разработки Android-версии

План разработки на 19 ноября 2026 года. Приложение предназначено для игроков на ПК. Телефон сам находит временные раздачи Steam, Epic Games Store и GOG, показывает, до какого момента игру можно получить навсегда, и открывает нужную страницу магазина. Пользователь забирает игру в магазине и сам ставит отметку «Уже забрал».

Первый результат разработки — локально устанавливаемый APK с одним магазином и рабочим переходом из уведомления. Для беты запланированы три магазина. После беты один подписанный APK сможет обслуживать прямую установку из GitHub Releases и обновления через Obtainium. Публикация в F-Droid — отдельный будущий этап.

## Что войдёт в бету

| Сценарий | Поведение |
|---|---|
| Найти раздачу | Лента активных раздач игр для ПК с выбором магазинов и страны. По умолчанию — US, как в расширении. Страна каталога и язык интерфейса выбираются независимо. Бесплатные выходные, постоянно бесплатные игры, демо и ещё не начавшиеся акции исключаются из ленты. |
| Успеть забрать | Проверка вручную и периодически в фоне, локальные уведомления о новых акциях, тихие часы и одно напоминание при известном сроке. Интервал по умолчанию — три часа. При неизвестном сроке карточка прямо сообщает об этом. |
| Открыть магазин | Нажатие на уведомление о действующей акции открывает страницу получения в браузере или приложении магазина. Для раздачи на главной GOG открывается главная. При известном истекшем сроке открывается запись со статусом «Завершена». |
| Сохранить результат | Локальные история и обратимая отметка «Уже забрал». Повторный опрос, перезапуск и обновление APK сохраняют отметку. Данные последней проверки доступны офлайн. |
| Понять, работает ли приложение | У каждого выбранного магазина видны время последной успешной проверки и состояние источника. Отказ в разрешении на уведомления сохраняет доступ к ленте и ручной проверке. Языки беты — русский и английский. |

После базовой беты первым кандидатом будет импорт резервной копии расширения с предпросмотром. Он позволит перенести уже полученные игры. Далее — скрытие одной кампании, игнорирование игры, отсрочка и дополнительные фильтры по запросам тестировщиков. Аккаунты FGW, облачная синхронизация, автоматическое получение игр и собственный сервер в объём проекта не входят.

## Источники раздач и совместимость с расширением

Отправная точка — расширение 2.2.1, ревизия `9e302be`. Предлагается переносить правила на Kotlin и хранить небольшие обезличенные примеры ответов вместе с ожидаемыми результатами в Android-репозитории. У каждого примера указывать тест и ревизию расширения. Сборка из чистого клона должна обходиться без соседнего репозитория, JS-движка и доступа к магазинам. Изменение классификации в одном проекте — повод прогнать тот же пример во втором. |---|---|---|

Нулевая цена в каталоге без условий раздачи также ничего не подтверждает. |

## Архитектура и мобильный интерфейс

- **Стек.** Нативный Kotlin, один модуль `:app`, одна Activity, Jetpack Compose и Material 3. Начать с пакетов для интерфейса, данных магазинов, хранения и фоновой работы. Зависимости передавать через конструкторы. Экран получает состояние через ViewModel, StateFlow и `collectAsStateWithLifecycle`. [Рекомендации Android](https://developer.android.com/topic/architecture/recommendations)
- **Данные.** Room хранит предложения, кампании, историю, отметки и журнал уведомлений. DataStore хранит настройки. Лента читает Room. У записи предложения есть магазин, внешний ID, страна, адрес получения, известные границы акции и время последнего подтверждения. У отметки «Уже забрал» ключ игры в магазине, у события уведомления — ключ кампании и тип события. Повторная раздача — новая кампания после подтверждённого окончания предыдущей. Смена страны требует новой проверки перед показом оповещений.
- **Проверка.** Кнопка и WorkManager используют один код опроса. Для каждого магазина он возвращает находки, полноту и ошибку. Отсутствие игры в ответе само по себе не завершает кампанию. При частичном ответе записываются подтверждённые находки, предыдущие данные помечаются временем проверки. Ограничить число страниц, параллельных запросов и время ожидания. При 429 учитывать `Retry-After`, повторять временные ошибки с увеличиваемой паузой. Обложки загружать по потребности на экране, оповещение должно работать без картинки.
- **Фон.** Одна уникальная периодическая задача WorkManager с условием подключения к сети. При пустом выборе магазинов отменять расписание. Совпавшие ручной и фоновый запуски объединять, результаты старого запроса после смены настроек отбрасывать. Перед доставкой повторно проверить срок, тихие часы, отметку и разрешение. Сохранить событие вместе с результатами сканирования в транзакции Room, отправить с устойчивым ID уведомления, отметить результат. После сбоя повторять публикацию под тем же ID с `setOnlyAlertOnce`. Срок запуска зависит от Doze и ограничений устройства, минимум периодической работы — 15 минут. Точные будильники и постоянно работающая служба для этого сценария не нужны. [WorkManager](https://developer.android.com/reference/androidx/work/PeriodicWorkRequest)
- **Приватность.** Только HTTPS к выбранным магазинам и нужным источникам. В описании Epic указать, когда телефон обращается к стороннему EGData и какие данные получает сервис — IP, регион и параметры запроса. Проверять схему и домен внешнего адреса перед переходом. Не использовать аккаунт, cookies или ключи пользователя. Отметки и история остаются локальными, включая явные правила исключения из облачного Android Backup. Фоновая работа и установка должны проходить также на образе AOSP без Google Play Services.
- **Главный экран.** Сначала игра, магазин и срок по местному времени, затем действия «Открыть магазин» и «Уже забрал» с возможностью отмены. Показать последнюю успешную проверку. Предусмотреть разные состояния для первой загрузки, отсутствия раздач, отключённых магазинов и устаревших данных. При ошибке одного источника остальные карточки остаются доступны. Основная навигация — раздачи, история и настройки.
- **Системный интерфейс.** На телефоне — одна колонка, на широком окне — список и подробности, навигация по доступной ширине окна. Учитывать системные отступы edge-to-edge, изменение размера окна и жест «Назад». Поддержать светлую и тёмную темы, масштаб шрифта, перенос названий, TalkBack, область нажатия от 48 dp. Срок, магазин и статус читаются без опоры на цвет. Разрешение `POST_NOTIFICATIONS` на Android 13+ запрашивать, когда пользователь включает оповещения. Разделить каналы новых раздач и напоминаний. [Адаптивные интерфейсы](https://developer.android.com/develop/ui/compose/layouts/adaptive/get-started-with-adaptive-apps) · [Доступность в Compose](https://developer.android.com/develop/ui/compose/accessibility/api-defaults) · [Уведомления](https://developer.android.com/develop/ui/compose/notifications/notification-permission)

## Среда сборки

Рабочее предложение — поддерживать Android 8.0 и новее (`minSdk 26`), собирать и тестировать под стабильный Android 17 (`compileSdk 37`, `targetSdk 37`). Нижняя граница упрощает работу с каналами уведомлений и датами. Её стоит пересмотреть, если первые тестировщики пользуются более старыми телефонами. ## Порядок разработки

| Этап | Что делаем | Условие перехода |
|---|---|---|
| 1. Первый APK | Создать Gradle-проект в корне, закрепить версии, собрать debug APK. Перенести один сохранённый пример Epic и отрицательный пример, затем подключить анонимную недельную ленту и переключение страны. Добавить Room, простую карточку и путь от фоновой проверки до системного уведомления. | На свежей установке ручная и фоновая проверки используют один провайдер. На реальном телефоне тестировщик видит оповещение и попадает к нужной игре. Пример проверяется и в неделю без активной раздачи. |
| 2. Бета для локальной проверки | Подключить Steam, GOG, прямой каталог Epic и EGData. Завершить историю, отметки, тихие часы, напоминания, диагностику, RU/EN и состояния ленты. | Для каждого магазина проходят положительные и отрицательные примеры, сбой одного источника сохраняет остальные, повторное сканирование не дублирует уведомления. |
| 3. Кандидат в бету | Выполнить матрицу устройств, полевой замер задержек и расхода, проверку доступности, миграцию данных и локальную репетицию двух подписанных версий. | Сохранены результаты из плана тестирования. Видны пропуски и причины задержек. При неприемлемой доставке пересмотреть интервал и поведение до выпуска. |
| 4. Распространение после решения о публикации | Собрать один универсальный APK, подготовить GitHub Release и ссылку Obtainium. Проверить установку и обновление через реальный канал. | Прямой APK и Obtainium устанавливают одну сборку, при обновлении сохраняются отметки. Проверка публикации возможна после появления разрешённого релиза. |

**Начальная задача разработчика** — зафиксировать время в примере `epicFeed(now)` из `tests/multistore-fixtures.mjs` и воспроизвести на Android его результат. Игра `123` попадает в ленту, будущая акция `456` остаётся вне ленты и уведомлений. Затем тем же кодом опросить Epic для US и RU. Сохранить полноту ответа, число запросов и время проверки по каждой стране. Пустая выдача допустима. Записанный пример `epic-mafia-hotel.json` относится к прямому каталогу на этапе 2.

Критерии приёмки, репетиция обновления и подготовка к F-Droid описаны в [плане тестирования и выпуска](TESTING-AND-RELEASE.ru.md).
